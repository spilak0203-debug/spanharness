## Platform facts (Claude Code 2.1.308)

Observed on Linux with Claude Code 2.1.308.

1. `${CLAUDE_PLUGIN_ROOT}` is substituted textually in exec-form `args` and in shell-form `command`, and exported as an env var to the hook process.
2. A handler whose command does not exist is silent in `-p` output. For an async handler it is not even shown in `--debug`; for a sync handler `--debug` shows a spawn error. Other handlers still run with full stdin.
   Async Stop handlers were sometimes `cancelled` at process exit and never ran (1 of 4 runs). Therefore spanharness uses one synchronous shell-form handler per event, with no `async`: `powershell -NoProfile -NonInteractive -ExecutionPolicy Bypass -File "${CLAUDE_PLUGIN_ROOT}/scripts/spanharness.ps1" record; sh "${CLAUDE_PLUGIN_ROOT}/scripts/spanharness.sh" record; exit 0`. `record` must be fast and always exit 0. On Linux `powershell` is missing, so `sh` gets stdin.
3. SubagentStop `agent_type` is `spanharness:<name>` (namespaced). SubagentStop keys: `session_id`, `transcript_path` (the parent's), `cwd`, `scratchpad_dir`, `prompt_id`, `permission_mode`, `agent_id`, `agent_type`, `effort` (object, e.g. `{"level":"low"}`), `hook_event_name`, `stop_hook_active`, `agent_transcript_path` (the subagent's own, `.../<session>/subagents/agent-<id>.jsonl`), `last_assistant_message`, `background_tasks`, `session_crons`. Stop has the same keys minus `agent_id`, `agent_type` and `agent_transcript_path`.
4. The style value is `spanharness:orchestrator`. The bare name `orchestrator` does not select it.
5. Marketplace `source: "./"` works (`validate --strict`, add, install, runtime).
6. A missing preloaded skill (for example `ponytail`): the agent starts and only a WARN appears in the debug log. A user skill at `~/.claude/skills/ponytail` is preloaded.
7. `PowerShell` in `tools:` on Linux: no warning, the agent loads.
8. `${CLAUDE_PLUGIN_ROOT}` is substituted in agent bodies and `SKILL.md`, but not in output-style text. The orchestrator style must not rely on `${CLAUDE_PLUGIN_ROOT}`.
9. `validate --strict` does not check agent frontmatter values (only a missing description) and does not inspect agents or skills unless pointed at `<dir>/agents`. The plugin's own `lint` is the real check.
10. A directory marketplace with `source: "./"` loads the plugin in place (`${CLAUDE_PLUGIN_ROOT}` is the source dir), although `installed_plugins.json` `installPath` shows a cache copy. Apply mode on a local clone therefore works.
11. `validate`, `marketplace add` and `install` work without login (with a sandbox `CLAUDE_CONFIG_DIR`).
12. `validate --strict` needs `author` in `plugin.json` and `description` in `marketplace.json`. README, LICENSE and icon only matter with `--profile directory`.

## Model choice per role: Claude Fable 5.2 (checked 2026-11-11)

Question: which roles should run on `fable` (Claude Fable 5.2) instead of `opus` (Claude Opus 5.5)?

- Official guidance: start with Opus, and move to Fable 5.2 where evals on Opus at higher effort still fall short. Effort default is `high`; use `xhigh` only for the hardest long-running coding and agentic work where a gain is measured. Price $8 / $40 per million tokens (Opus 5.5: $4 / $20). Source: https://platform.claude.com/docs/en/models/fable-5-2/whats-new-fable-5-2 (official).
- Launch numbers, all self-reported by Anthropic; no independent results yet. Source: https://llm-stats.com/blog/research/claude-fable-5-2-launch, cross-checked for SWE-bench Pro and FrontierSWE v2 against https://benchlm.ai/models/claude-fable-5-2. SWE-bench Multimodal differs across sources (74.1% self-reported, 62.29% on https://www.vals.ai/models/anthropic_claude-fable-5-2).

| Benchmark | Fable 5.2 | Opus 5.5 | Bears on |
|---|---|---|---|
| BenchCAD 2.1 Core, with tools | 83.5 | 65.3 | modeler |
| BenchCAD, without tools | 75.4 | 49.0 | modeler |
| RoboDojo Sim | 64.9% | 39.4% | modeler (mechanisms) |
| SWE-bench Multimodal | 74.1% | 61.4% | designer (screens), weak |
| Chartography, no tools | 73.4% | 64.4% | designer (visual), weak |
| GDPval-AA v2.1 Elo | 1831 | 1866 | designer (wording, knowledge work), favours Opus |
| FrontierSWE v2 | 69.9% | 62.3% | architect, coder |
| SWE-bench Pro | 93.0% | 89.9% | coder |

- Effort on Fable 5.2, FrontierCode 2.0 (self-reported): high 45.3% at $6.72 per task, xhigh 49.1% at $14.19, max 45.7% at $44.70.
- No published benchmark covers code review or bug finding, creative writing, or UI design.

Conclusions:
- modeler on `fable`: supported by the CAD and simulation rows (evidence: self-reported, confidence medium).
- designer on `fable`: not decided by benchmarks; visual rows favour Fable, knowledge-work rows favour Opus. Moved to `fable` as a trial, judged by the lessons records (confidence low).
- circuit on `fable` at `high`: no benchmark covers circuit design; chosen because miswiring damages parts and the judgment is calculation-heavy (evidence: reasoning, not measured, confidence low).
- architect on `fable` at `high`: the long-horizon rows favour Fable, and on FrontierCode 2.0 Fable at `high` (45.3%) matches the best Opus setting (45.5% at `max`) at about half the cost of Fable at `xhigh`. No benchmark measures design quality directly (evidence: self-reported, confidence medium).
- deep-reviewer stays at `xhigh`: no review benchmark, and on coding `xhigh` is the only level above `high` that gains (confidence low).

## PCB design with KiCad from scripts (checked 2026-11-13)

Question: how can an agent with only files and a shell design a PCB in KiCad 10 and produce JLCPCB-ready files? Install checked: `C:\Program Files\KiCad\10.0` has `bin\kicad-cli.exe`, `bin\python.exe` and `bin\Lib\site-packages\pcbnew.py` + `_pcbnew.pyd`. The research pass itself ran no commands, so the runtime behaviour below is from docs and reports unless marked "Measured"; the measured notes at the end of this section (2026-11-13, KiCad 10.0.8) override it.

Scripting state (KiCad 9 / 10 / 11)
- The IPC API (`kipy`, package `kicad-python`) in KiCad 9 and 10 only talks to a running GUI, has no plot/export, and only supports plugins in the PCB editor. Headless via `kicad-cli` and schematic-editor plugins arrive in 11. Official, confidence high. https://dev-docs.kicad.org/en/apis-and-binding/ipc-api/for-addon-developers/ ; devlist thread (KiCad dev: "won't be removed in 10", eeschema API "not enough time for 10", headless "hasn't been implemented yet") https://groups.google.com/a/kicad.org/g/devlist/c/3e8OU0FiEHc
- The SWIG `pcbnew` module is deprecated since 9.0; official docs plan removal in 11.0, and it is absent from 10.99 nightlies. https://dev-docs.kicad.org/en/apis-and-binding/pcbnew/ . The installed 10.0 `pcbnew.py:63` still ships it and warns "deprecated and will be removed in a future version"; it exposes `ExportSpecctraDSN(board, path)` (line 9944), `ImportSpecctraSES` (line 9955), `FootprintLoad` (line 24223). So on 10.0 the only GUI-free board scripting is SWIG run with `C:\Program Files\KiCad\10.0\bin\python.exe` (confidence high that it exists; medium that DSN/SES work with no GUI).
- Headless DSN/SES: a repo script claims `ExportSpecctraDSN` -> Freerouting -> `ImportSpecctraSES` -> save works on KiCad 9+ (https://git.sub-net.at/submodular/SN-L00/raw/branch/master/hardware/kicad/scripts/autoroute.py, seen only via a search summary); a kicad-mcp page says KiCad 9 cannot export the DSN headlessly (summary only); a 2023 forum thread says SES import needs a pcbnew window, unresolved on the page (https://forum.kicad.info/t/gui-agnostic-import-for-specctra-session-to-allow-headless-scripted-auto-routing/41063). Sources disagree. Measured on KiCad 10.0.8 here: `NewBoard`, `FootprintLoad`, `ExportSpecctraDSN` and `ImportSpecctraSES` run headless and return True; Freerouting itself was not run. Still check the return value of each call.
- Freerouting CLI: `java -jar freerouting.jar -de in.dsn -do out.ses` (README recommends JRE 25); routing takes minutes to hours; maintainer time is limited. https://github.com/freerouting/freerouting (official, confidence high for the flags `-de -do -inc`).

Schematic and netlist
- Hand-writing `.kicad_sch` is the least reliable route: needs x/y/rotation, inverted Y, 1.27 mm grid; reports of invented pins and invalid UUIDs; HWE-Bench spec-to-schematic top score 8.15% (cited on a historical page, so low-medium). https://pd.takazudomodular.com/docs/learning/ai-circuit-design-research/ ; a KiCad9 bare keyword mis-serialized by `kicad-sch-api` made `kicad-cli` drop sheets (search summary only).
- Preferred: connectivity first (net table), then a code-first tool. SKiDL README: supports KiCad 5-10, `generate_netlist(tool=KICAD10)`, `generate_schematic()` and `generate_svg()` (6-10), needs `KICAD_SYMBOL_DIR` set to `C:\Program Files\KiCad\10.0\share\kicad\symbols`. https://github.com/devbisme/skidl (official README). Conflict: the takazudo page says SKiDL gives only a netlist; the README is newer, so trust it but verify the schematic opens and passes `sch erc`.
- atopile: builds update `.kicad_pcb`; README names no KiCad version and no LCSC; the takazudo page says it gives no readable schematic. Not verified for KiCad 10; do not make it the default. https://github.com/atopile/atopile
- `kicad-cli` has no netlist-to-PCB import (not in the CLI reference); "Update PCB from Schematic" is a GUI action. Inference: the agent must build the board with pcbnew SWIG (`FootprintLoad`, set pad nets from the exported netlist) or SKiDL, then use `pcb drc --schematic-parity` as the cross-check (confidence low-medium; no source shows this end to end on 10).
- Netlist export: `kicad-cli sch export netlist --format kicadsexpr|kicadxml|... -o out`. https://docs.kicad.org/10.0/en/cli/cli.html

Footprints and parts
- Stock libraries are in `C:\Program Files\KiCad\10.0\share\kicad\{symbols,footprints}` (e.g. `Resistor_SMD.pretty\R_0603_1608Metric.kicad_mod` exists). KiCad 10 ships STEP only for 3D models. https://www.kicad.org/blog/2026/03/Version-10.0.0-Released/
- `easyeda2kicad --full --lcsc_id=C2040 --output <dir>` writes `.kicad_sym`, `.pretty`, `.3dshapes`; README: "supports KiCad v6 and newer", correctness "can't be guaranteed". On Windows use `python -m easyeda2kicad`. https://github.com/uPesy/easyeda2kicad.py (official). Footprint check against the datasheet must be explicit: pad count, pitch, pad size, pin 1 and polarity. Reports: an AI missed the through holes on a coin-cell footprint and made a pad too small (https://news.ycombinator.com/item?id=49569366, opinion); vision models score IoU 11.1% on footprint geometry (https://arxiv.org/html/2508.03725v1, search summary only).
- Prefer JLCPCB Basic parts; query real JLCPCB data rather than a generic part search (the KiCad MCP report found search results unreliable). https://jlcpcb.com/blog/kicad-mcp-how-to-design-a-pcb-with-claude-code (vendor blog, measured on one board, confidence medium).

Checks
- `kicad-cli pcb drc` / `sch erc`: `--format json`, `--severity-all`, `--units mm`, `-o`; `--exit-code-violations` returns 0 or 5. `pcb drc` also has `--schematic-parity`, `--refill-zones --save-board`, `--all-track-errors`. https://docs.kicad.org/10.0/en/cli/cli.html (official, high). Without `--exit-code-violations` the exit code is not a signal; read the JSON.
- ERC and DRC passing is not correctness: a label collision shorting ISENSE to ISET gave only an ERC warning and was found by a pin-by-pin netlist comparison; zero DRC errors does not prove the pin map. Same JLCPCB blog; corroborated by https://pd.takazudomodular.com/docs/learning/ai-circuit-design-research/ (pin-18 bug the ERC missed). Confidence medium-high.
- JLCPCB limits (1 oz, official): 2-layer trace/space 0.10/0.10 mm, 4-layer 0.09/0.09 mm; min drill 0.15 mm; PTH annular ring 2-layer 0.25 recommended / 0.18 min, 4-layer 0.20 / 0.15; pad-to-pad 0.15 mm; copper-to-edge 0.2 mm (V-cut 0.4); silkscreen line 0.15 mm, text height 1.0 mm. https://jlcpcb.com/capabilities/pcb-capabilities . Rules can go in `<project>.kicad_dru` (community files for JLCPCB exist: https://github.com/Cimos/KiCad-CustomDesignRules, KiCad 8 syntax, summary only); a KiCad 10 graphical rule editor reads the same custom-rules language (https://www.cnx-software.com/2026/03/22/kicad-10-release-dark-mode-graphical-drc-rule-editor-new-file-importers-and-more/ , summary only).
- Trace current: IPC-2221 `I = k * dT^0.44 * A^0.725`, k = 0.048 outer, 0.024 inner, A in mil^2 (https://protoexpress.com/blog/ipc-2221-circuit-board-design, and a second source via search summary at Altium/others); IPC-2152 is the newer standard and uses correction factors, IPC-2221 is the conservative one. Use outer layers and a margin; confidence medium. KiCad's own `pcb_calculator.exe` is installed but is a GUI program.
- Voltage clearance: sources disagree. protoexpress (IPC-2221B Table 6-1 values): external uncoated 0-30 V 0.1 mm, 31-150 V 0.6 mm, 151-250 V 1.25 mm, 301-500 V 2.5 mm; coated 0.05 / 0.13 / 0.4 / 0.8. The JLCPCB blog table (https://jlcpcb.com/blog/pcb-voltage-clearance-guide) gives much smaller values (0.15 mm at 51-100 V). Use protoexpress (matches the standard table as quoted by a second page in search results); IPC-2221 is not a safety-isolation standard, so mains-level work needs a human and the product standard. Confidence medium.

Outputs (JLCPCB)
- Commands (official CLI reference): `pcb export gerbers -l <layers>` (flags: `--subtract-soldermask`, `--use-drill-file-origin`, `--check-zones`, `--no-x2`), `pcb export drill --format excellon --excellon-separate-th --generate-map -u mm`, `pcb export pos --format csv --units mm --side both --smd-only --exclude-dnp`, `sch export bom --fields ... --labels ... --group-by ... --exclude-dnp`. KiCad 10 changes: HPGL export is dead, `--include-excluded-from-bom` has no effect, `pcb export ipc2581 --version B|C`. https://docs.kicad.org/10.0/en/cli/cli.html
- BOM columns JLCPCB expects: Comment, Designator, Footprint, LCSC Part # (csv/xls/xlsx). CPL columns: Designator, Mid X, Mid Y, Rotation, Layer, in mm, one file with Top/Bottom (T/B accepted). KiCad `.pos` headers are Ref, PosX, PosY, Rot, Side and must be renamed. https://jlcpcb.com/help/article/how-to-generate-the-bom-and-centroid-file-from-kicad (official) ; same names in KiBot's JLCPCB config https://kibot.readthedocs.io/en/master/notes_position.html (KiBot also adds Val and Package; those are extra, not required). Confidence high. The official "advice" page adds: BOM designators must equal CPL designators including case, max 200 designators per BOM line, one designator once, 0.2 mm min spacing between CPL entries. https://jlcpcb.com/help/article/advice-for-bom-and-cpl-files-preparation
- Rotation: KiCad zero rotation differs from the pick-and-place tape orientation for many parts (QFN, SOT-23, SOT-223, WS2812); bottom side is handled differently by JLCPCB (not mirrored as of Nov 2023, per KiBot). Per-part fix fields: `JLCPCB Rotation Offset` / `JLCRotOffset` (KiBot, JLC plugin) or `FT Rotation Offset` (Fabrication Toolkit), positive = counter-clockwise. Built-in table examples: `^QFN-` 270, `^SOT-23` 180. No script can verify this; the JLCPCB order preview is the check. https://kibot.readthedocs.io/en/master/notes_position.html , https://github.com/bennymeg/Fabrication-Toolkit . Confidence high that it is a real issue, medium on the specific angles.
- Fabrication Toolkit has a CLI (`python -m plugins.cli -p board.kicad_pcb`, flags `--autoTranslate/-t --autoFill/-f --excludeDNP/-e`) producing gerbers, `bom.csv`, `positions.csv` and netlist; KiCad 10 not stated, and it needs the KiCad Python environment. Use it as a cross-check or fallback, not as a dependency. https://github.com/bennymeg/Fabrication-Toolkit (summary of README, confidence medium).

Review without a GUI
- `kicad-cli pcb render -o out.png --side top|bottom|... -w -h --quality high`, `pcb export svg --mode-multi --fit-page-to-board --exclude-drawing-sheet -t`, `pcb export pdf --mode-multipage`, `sch export pdf`, SKiDL `generate_svg()`. The agent can read PNG/SVG-as-image output by opening the png with a file reader. Official CLI reference; whether a model reads layout accurately from images is unproven (LLMs read layouts better than they produce them, takazudo page, low-medium).

What an agent can and cannot do (opinion-level, from practitioners)
- Works: netlist-driven schematic, parts choice, datasheet cross-check of the netlist, simple 2-layer placement with an overlap check, grid/A* or Freerouting routing of low-speed boards, DRC loops. One report routed a 3-layer RP2040 board that "worked on the first go"; another says LLM routing "completely breaks down" and auto-layouters failed on basic tasks. https://news.ycombinator.com/item?id=49569366 (opinion, mixed, confidence low-medium).
- Weak or needs a human: RF and impedance-controlled lines, high-speed buses and diff-pair length, switching-regulator loop placement (a first routing pass put a feedback trace next to the switching node and needed a 1.2 mm keepout), thermal, EMC, mains isolation, 3D/mechanical fit, connector footprints and pin 1 polarity, final rotation check on the JLCPCB preview, and the decision to order. The JLCPCB KiCad MCP author had not fabricated or bench-tested the board. Sources: https://jlcpcb.com/blog/kicad-mcp-how-to-design-a-pcb-with-claude-code , https://news.ycombinator.com/item?id=49569366 . Confidence medium.
- Pitfalls seen: invented pins and UUIDs in raw s-expressions; stacked multi-unit parts; double-run placement scripts drawing the outline twice; router edge clearance (0.35 mm) below the DRC rule (0.5 mm); IPC server needs a single GUI instance and no modal dialog (only if the IPC route is used). Read-only default plus a git-tracked sandbox folder limited damage.
- Related agent tooling for reference: https://github.com/aklofas/kicad-happy (analysis/DFM/JLCPCB skills; its own README says tests check stability, not correctness).
- Measured on this machine (2026-11-13): `kicad-cli.exe version` prints 10.0.8 and `pcb` has drc · export · import · render · upgrade. KiCad's `bin\python.exe -I -c "import pcbnew"` works without the GUI and exposes `ExportSpecctraDSN`, `ImportSpecctraSES`, `FootprintLoad`, `NewBoard` (calls not run). Java (needed by Freerouting) and SKiDL are not installed. Evidence: measured, confidence high for presence, none for end-to-end behavior.
- Measured on KiCad 10.0.8 (2026-11-13, reviewer runs; calls and exit codes seen, not a full routed board): a zone is exported to the DSN as `(plane GND ...)`; a valid `.kicad_dru` is applied; a `.kicad_dru` with any error is silently ignored (exit 0, no rule violations, empty stderr), so test it with an impossible limit; `pcb drc --schematic-parity` exits 0 with `"schematic_parity": []` when the `.kicad_sch` is missing or has another base name, and with it present a swapped pad net gives `net_conflict` at severity warning; `--refill-zones` without `--save-board` gives exit 0 and leaves the file unfilled, and `pcb export gerbers` without `--check-zones` silently omits unfilled pours; `kicad-cli` messages and JSON descriptions are localized (parse the `type` keys, read files as UTF-8); `pcb export pos` defaults to inches.
- SKiDL 3.0.0 (2026-10-16) has `KICAD10` for `generate_netlist` and has `generate_schematic()` (KiCad 6-10).
